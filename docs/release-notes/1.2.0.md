In this release, `usfrip` rips the music of Gex 64: Enter the Gecko and writes much smaller sets, and the rips of 13 games start sooner and decode faster in the legacy players. Rip those 13 games again (see below). usf rips Nintendo 64 music into USF, the PSF-family format for the Nintendo 64, and plays it by running the game's code on an emulated console. The release comes with a ripper (`usfrip`), a renderer (`usfplay`), a foobar2000 component and an XMPlay plugin.

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. To install the XMPlay plugin, unzip `xmp-usfplay-1.2.0.zip` and put `xmp-usfplay.dll` in the XMPlay folder, or in a folder inside it. Then restart XMPlay. For macOS, the README explains how to build from source.

## Rip these games again

Rips of these games made with 1.1.1 or an earlier release start late and decode slowly in the legacy players. They also make the game's sound call for each frame in the wrong order. Rip them again with this release:

- Chameleon Twist
- The Legend of Zelda: Majora's Mask
- The Legend of Zelda: Ocarina of Time
- Mario Kart 64
- Mario Tennis
- Paper Mario
- Pokémon Puzzle League
- Super Mario 64, its music and its sound effects
- Yoshi's Story
- the Aleck64 games Hanabi de Doon! - Don-chan Puzzle, Kurukuru Fever, Magical Tetris Challenge and Tower & Shaft

## Changes since 1.1.1

### Gex 64

- `usfrip` rips the music of Gex 64: Enter the Gecko (USA): 27 tracks. They are the 12 songs that the levels start, 9 that the levels' scripts start, 2 that the game never plays and the 4 short songs of the extras.
- The tracks play at the game's default music volume. The game's options can raise it by up to 12 dB.

### Smaller sets

- The library of a set now contains every ROM word that a track reads, and each mini contains only its track number and the few words of the save state that the track changes. A mini is a few hundred bytes, where it was tens or hundreds of kilobytes.
- The library leaves out the words of RDRAM that are zero. The USF format has a player fill the save state with zeros before it loads a set. Those words therefore still read as zero.
- Sets are much smaller than the ones 1.1.1 made. The layout doesn't change what a set plays. Sets made with 1.1.1 still play. The games that aren't listed under "Rip these games again" need a new rip only for the smaller files.

### Rips that start late in the legacy players

- In the games listed under "Rip these games again", the ripper's driver waited for each video field in a loop that reads the current line of the video interface. The legacy players run every instruction of such a loop. They skip only an idle loop, a branch to itself. These rips therefore decoded several times slower than other sets in the legacy players, and a track could start about a second late. usf's players weren't slowed.
- The driver now waits for the game's retrace message, as the game's threads do. The game's idle thread runs meanwhile, and the legacy players skip it.
- The driver now makes the game's sound call for each frame after the audio thread's work for that field. That is the order the game uses. Before, the call came first. The game's commands can now reach the sound engine one field later than before. Some tracks therefore sound slightly different. Music that picks phrases at random, such as Hyrule Field in Ocarina of Time, picks other phrases.
- `usfrip` rips these games far faster too.
