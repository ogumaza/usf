In this release, two tracks of Mario Kart 64 and one track of Wave Race 64 end after the second pass of their music. usf rips Nintendo 64 music into USF, the PSF-family format for the Nintendo 64, and plays it by running the game's code on an emulated console. The release comes with a ripper (`usfrip`), a renderer (`usfplay`), a foobar2000 component and an XMPlay plugin.

## Downloads

| File | Contents |
|---|---|
| `usf-1.0.1-win-x64.zip` | `usfrip` and `usfplay` for 64-bit Windows |
| `foo_input_usfplay-1.0.1.fb2k-component` | the foobar2000 component, for 64-bit and 32-bit foobar2000 v2 |
| `xmp-usfplay-1.0.1.zip` | the XMPlay plugin, for XMPlay 3.8.2 or later |

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. To install the XMPlay plugin, unzip `xmp-usfplay-1.0.1.zip` and put `xmp-usfplay.dll` in the XMPlay folder, or in a folder inside it. Then restart XMPlay. For macOS, the README explains how to build from source.

## Changes since 1.0.0

### Track lengths

- `usfrip` sets the length of a track from the part of its sound that loops last. In Mario Kart 64, sequence player 2 runs the script of the sound effects beside the music. That script loops later than the music. Sequences 0x10 and 0x12 therefore got lengths far past the second pass of their music, and sequence 0x12 ran on to the limit of 600 s.
- Wave Race 64's sequence 0x02 never repeats exactly. It also ran on to the limit of 600 s.
- The profiles of the two games now set the lengths of these three tracks. Each length covers about two passes of the music and ends with a fade of 10 s.

The limitations listed for 1.0.0 still apply. See "Known gaps" in the README for the details.
