In this release, `usfrip` warns when a folder or an archive holds the chips of more than one Aleck64 game, and the players accept a set with an empty `_lib2` tag. usf rips Nintendo 64 music into USF, the PSF-family format for the Nintendo 64, and plays it by running the game's code on an emulated console. The release comes with a ripper (`usfrip`), a renderer (`usfplay`), a foobar2000 component and an XMPlay plugin.

## Downloads

| File | Contents |
|---|---|
| `usf-1.1.1-win-x64.zip` | `usfrip` and `usfplay` for 64-bit Windows |
| `foo_input_usfplay-1.1.1.fb2k-component` | the foobar2000 component, for 64-bit and 32-bit foobar2000 v2 |
| `xmp-usfplay-1.1.1.zip` | the XMPlay plugin, for XMPlay 3.8.2 or later |

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. To install the XMPlay plugin, unzip `xmp-usfplay-1.1.1.zip` and put `xmp-usfplay.dll` in the XMPlay folder, or in a folder inside it. Then restart XMPlay. For macOS, the README explains how to build from source.

## Changes since 1.1.0

### The ripper

- When a folder or a ZIP archive holds the chips of more than one Aleck64 game, `usfrip` rips the first of them, as before, and now names the others. Give each game a folder or an archive of its own.
- An error in the check of one track is reported for that track. Before, it could end `usfrip`.
- When `usfrip` can't create the output folder, it says why.

### The players

- `usfplay`, the foobar2000 component and the XMPlay plugin skip an empty `_lib2` tag, or a later empty `_libN` tag, as they already skipped an empty `_lib` tag. Before, they rejected the set.

## Known limitations

The limitations listed for 1.0.0 still apply. See "Known gaps" in the README for the details.
