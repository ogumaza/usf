usf 1.0.0 is the first release of usf. usf rips Nintendo 64 music into USF, the PSF-family format for the Nintendo 64, and plays it by running the game's code on an emulated console. The release comes with a ripper (`usfrip`), a renderer (`usfplay`), a foobar2000 component and an XMPlay plugin.

## Downloads

| File | Contents |
|---|---|
| `usf-1.0.0-win-x64.zip` | `usfrip` and `usfplay` for 64-bit Windows |
| `foo_input_usfplay-1.0.0.fb2k-component` | the foobar2000 component, for 64-bit and 32-bit foobar2000 v2 |
| `xmp-usfplay-1.0.0.zip` | the XMPlay plugin, for XMPlay 3.8.2 or later |

The programs run on Windows 10 or later and require no runtime DLLs. To install the component, open the file with foobar2000, or add it under Preferences › Components. To install the XMPlay plugin, unzip `xmp-usfplay-1.0.0.zip` and put `xmp-usfplay.dll` in the XMPlay folder, or in a folder inside it. Then restart XMPlay. For macOS, the README explains how to build from source.

## Features

- **Ripping.** `usfrip` rips a Nintendo 64 cartridge image (`.z64`, `.v64` or `.n64`) into a `.usflib` and a `.miniusf` for each track. It boots the game on the emulated console and runs it to a point just before a track starts. Each track runs from the save state there, with its number in the mini. Each mini keeps only the parts of the cartridge that its track reads. `usfrip` plays each track to find its length and fade, and checks each mini against the untrimmed state at the end. Drag and drop also works on Windows.
- **Game profiles.** `usfrip` rips the games that it has a profile for: Chameleon Twist (USA, revision 1), Chameleon Twist 2, Cruis'n World, GoldenEye 007, Hey You, Pikachu!, The Legend of Zelda: Majora's Mask, The Legend of Zelda: Ocarina of Time (USA, revision 2), Mario Kart 64, Mario Tennis, Paper Mario, Pokémon Puzzle League, Pokémon Snap, Pokémon Stadium (USA, revision 2), Pokémon Stadium 2, Wave Race 64 (USA, revision 1), and the sound effects of Super Mario 64 (all USA). The two Zelda games require a dump of the console's PIF ROM.
- **The emulator core.** The core emulates the VR4300 CPU with its FPU and TLB, the RSP with its vector unit, the interfaces of the RCP, the PIF and the boot. It runs the game's audio microcode on the emulated RSP. The mixing therefore matches the console.
- **Rendering.** `usfplay` renders rips to WAV or FLAC at the rate that the game sets on its audio interface, without resampling. On macOS, the build makes `usfplay.app` too. Drop files on it in the Finder.
- **foobar2000 and XMPlay.** The component and the plugin play `.miniusf` and `.usf` files with their length and fade tags. They render ahead of playback on a separate thread and buffer up to 10 minutes of audio. Seeking within the buffer is instant. The component supports tag editing, ReplayGain and endless playback.
- **Existing sets.** The players play the USF sets that older rippers made, with the timing of the older players and the `_enablecompare` and `_enableFIFOfull` flags of each set. The sets that `usfrip` makes play in the older players too.

## Known limitations

- The emulation is heavy. A 32-bit build is slower than a 64-bit one. Use 64-bit foobar2000 and the 64-bit component where you can.
- A track plays as the older players play it, but not always sample for sample.
- Seeking back before the buffered audio renders again from the start of the track.
- foobar2000 shows the sample rate of a track only during playback.
